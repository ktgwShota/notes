bfcache diagnostics

bfcache が効かない理由

戻る／進むの操作自体は正しく行われているのに、ページが復元されず再読み込みになるときのチェックリスト。ブラウザごとの判定と、同じ端末でも人によって差が出る要因をまとめています。

前提

同一タブ内の履歴移動（戻る／進むボタン、history.back()）であり、ページのロードは完了している。この条件を満たさない遷移はそもそも bfcache の対象外です。

ブロックしないもの（よくある誤解）

原因として疑われがちですが、実際には bfcache を妨げません。ここを直しても状況は変わらないので調査対象から外して構いません。

  • beforeunload 離脱確認ダイアログを出すリスナー。unload と混同されがちですが、bfcache はブロックしません。
  • pagehide / visibilitychange むしろ unload の代替として推奨されている書き方。計測処理はこちらへ寄せるのが正解です。
  • Service Worker 制御下にあること自体は問題ありません。復元中に SW が更新された場合のみ破棄されます。
  • sessionStorage / localStorage 読み書きの有無は判定に影響しません。復元時も内容はそのまま維持されます。
  • setTimeout / setInterval タイマーは破棄されず凍結され、復元時に再開します。残っていてもブロック要因にはなりません。

原因を特定する手順

ブラウザが理由を直接教えてくれるので、推測より先に API とツールで確定させるのが最短です。

  1. 戻った先のページで notRestoredReasons を読む 復元されなかった理由が構造化データで返ります。実ユーザー環境での調査にはこれが最も確実です。 
    performance.getEntriesByType('navigation')[0].notRestoredReasons
  2. DevTools の bfcache テストを実行する Chrome の Application → Back/forward cache → テスト実行。実際に離脱・復帰を再現して、阻害要因を項目名で一覧表示してくれます。
  3. レスポンスヘッダーの Cache-Control を確認する Network タブでドキュメント自身のレスポンスを開き、no-store が付いていないか確認します。付いていれば Safari / Firefox では確定でアウト。
  4. 拡張機能を切って、シークレットウィンドウで再現する 個人差の切り分け用。拡張なしで発動するなら原因は端末環境側、それでも発動しないならページ側の要因です。
判定は 2026 年 9 月時点の各ブラウザの挙動に基づく整理です。Chrome の「条件付き」項目は段階展開の対象で、同一バージョン内でも差が出ます。実環境での確認は必ず notRestoredReasons で行ってください。
