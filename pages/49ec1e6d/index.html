history api

ユーザー操作なしで追加した履歴は戻るボタンで飛ばされる

Chromium には、ユーザーが一度も操作していないページが追加した履歴を、ブラウザの戻るボタンで飛ばす仕組みがあります（history manipulation intervention）。ページを開いた直後に pushState で履歴を足して「戻る」を検知しようとすると、戻るボタンで前のサイトまで戻ってしまい、popstate は発火しません。

前提

history.pushState でダミーの履歴を足し、戻る操作を popstate で拾う実装の話です。離脱時のポップアップ、モーダルを戻るで閉じる処理、SPA のルーティングなどが該当します。

何が起きるか

ページを開いた時点で履歴を 1 つ足し、戻る操作を検知しようとするコードです。

// ページを開いた直後に、戻る操作を拾うための履歴を足す
history.pushState({ guard: true }, '')

window.addEventListener('popstate', () => {
  showLeavePopup()
})
  1. a.example から b.example のリンクを踏む b.example を開いた時点で上のコードが動き、b.example の履歴が 2 つになります。
  2. b.example で何も操作せずに戻るボタンを押す スクロールして読んでいるだけで、タップやクリックはしていない状態です。
  3. b.example の履歴がまとめて飛ばされ、a.example に戻る b.example は離脱するだけなので popstate は発火せず、ポップアップも出ません。

一度でもページをタップしてから戻るボタンを押すと、想定どおり popstate が発火します。操作するかどうかで結果が変わるので、動作確認では再現しないことがあります。

判定のルール

Chromium のドキュメントに書かれている条件です。

  • ユーザー操作がないまま履歴を足すと、そのページの履歴がすべて「飛ばす対象」になる pushState だけでなく、ユーザー操作なしの別ページへの遷移（リダイレクト）も対象です。同じドキュメント内の履歴はすべて同じ扱いになります。
  • 一度でもユーザー操作があれば解除される 履歴を足す前でも後でも、ページが一度ユーザー操作を受け取れば、そのページの履歴は飛ばされなくなります。iframe の中での操作も含みます。
  • 「ユーザー操作」はクリック・タップ・キー入力 HTML 仕様の user activation のことで、マウスのボタン押下、タップの終わり、キー入力（Esc を除く）などで得られます。スクロールやマウスの移動、ページを読み込んだだけでは得られません。
  • 対象は戻る・進むボタンだけ history.back() などの JS からの操作は影響を受けません。仕様が定めているのは JS の API の挙動だけなので、ボタンの挙動はブラウザが独自に決めています。
  • すべてが飛ばす対象だと、戻るボタンが効かなくなる Android ではタブが閉じます。デスクトップでは戻るボタンを押しても何も起きず、長押しの履歴一覧から明示的に選ぶ必要があります。
補足

WebKit（Safari と、iOS 上のすべてのブラウザ）にも、JS がユーザー操作なしに足した履歴を戻る操作で飛ばす仕組みがあります。ただし条件が Chromium と同じかは確認できていないので、ここは確度が低い情報です。Firefox の挙動は確認していません。

どう防ぐか

履歴はユーザー操作の後に足します。そのうえで、戻る操作を必ず検知できるとは考えずに設計します。

  • 最初のクリックかキー入力で履歴を足す user activation を得た後なら、その履歴は飛ばされません。対応ブラウザでは navigator.userActivation.hasBeenActive で、すでに操作があったかを確かめられます。
  • 戻る操作を検知できない場合を前提にする 何も操作せずに離脱するユーザーには、履歴を足す機会がありません。離脱時の処理を戻る操作だけに頼らず、visibilitychange など別の手段も検討します。
  • DevTools の Issues パネルで確かめる Chromium は、履歴が飛ばす対象になったときに Issues パネルへ理由を出します。何も操作せずに戻ったときにここへ出ていれば、この仕組みが原因です。 
const insertGuardHistory = () => {
  history.pushState({ guard: true }, '')
}

if (navigator.userActivation?.hasBeenActive) {
  insertGuardHistory()
} else {
  const events = ['click', 'keydown']
  const handleFirstActivation = (event) => {
    // Esc キーは user activation にならない
    if (event.type === 'keydown' && event.key === 'Escape') return
    events.forEach((type) => window.removeEventListener(type, handleFirstActivation))
    insertGuardHistory()
  }
  events.forEach((type) => window.addEventListener(type, handleFirstActivation))
}

タッチ操作は pointerdown の時点ではまだ user activation になっていないので、click を使います。
