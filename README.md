# notes

調べたことを 1 枚のページにまとめて置いておく場所。

サイトとして回遊してもらうものではなく、**「これ見て」と単体のページの URL を個別に渡す**ための置き場です。トップページは共有用ではなく、自分が過去のページを探すための一覧として置いています。

**https://ktgwshota.github.io/notes/**

---

## ⚠️ 公開可否チェック

**このサイトはインターネット上の誰でも読めます。アクセス制限はありません。**

push する前に必ず全文を走査してください。以下が 1 つでも含まれていたら、**そのページは公開しない**。

| 分類 | 具体例 |
| --- | --- |
| 顧客・取引先の情報 | 企業名、サービス名、案件コード、顧客サイトの URL・ドメイン |
| 社内システムの情報 | リポジトリ名、内部ツール名、管理画面・Notion・Jira・Sentry の URL |
| ソースコード由来の情報 | 自社コードの抜粋、ファイルパス、関数名、テーブル名、カラム名、API エンドポイント |
| 認証情報 | トークン、API キー、パスワード、環境変数の値 |
| 個人情報 | 氏名、メールアドレス、アカウント名、Slack の発言 |
| 事業情報 | 売上、KPI、ユーザー数、契約条件、未公開の機能やリリース予定 |
| 障害・インシデント | 発生日時、影響範囲、原因の詳細 |

**グレーだと感じた時点で「含まれている」と判定します。** 公開することより、公開してはいけないものを出さないことが優先です。

### 社内の調査がきっかけのとき

一般的な技術知識として成立する形に書き直します。固有名詞を消すだけでは足りません。調査の経緯や結論が特定の案件に紐づいたままなら、まだ書き直しが必要です。

- ❌ 「◯◯社のサイトで計測タグが原因で bfcache が効かなかった」
- ⭕ 「計測タグが `unload` を使っていると bfcache が無効になる」

前提知識のない人が読めて、かつ誰にでも当てはまる内容になっていれば合格です。

> Claude Code で作る場合は `add-note` スキルを使ってください。このチェックが手順に組み込まれています。

## ページを追加する

```
python3 scripts/new_page.py "ページタイトル" --description "要約" --tags browser,performance
```

生成された `<id>/index.html` の中身を書き、公開可否チェックを済ませて main に push します。反映まで 30 秒〜2 分です。

`--description` は一覧とリンクプレビューの両方に出るので、1 文で内容が分かるように書きます。

## パーマリンク

URL は `https://ktgwshota.github.io/notes/<id>/` の形式で、`<id>` はランダムな 8 桁の 16 進数です。意味のある名前は付けません。

- URL の可読性に価値がない。回遊されず、常に個別の URL を直接渡すため
- トピック名を slug にすると、同じテーマの 2 枚目が置けなくなる（`/bfcache/` を使うと bfcache の別の話を置けない）
- ID を機械が決めることで、命名を考える工程そのものがなくなる

共有相手がリンク先を判断する手がかりは OGP が担います。`new_page.py` が `og:title` と `og:description` を埋めるので、Slack に貼るとタイトルと要約がプレビュー表示されます。

## トップページの一覧

**push 時に GitHub Actions が自動生成します**（[build-index.yml](.github/workflows/build-index.yml)）。`index.html` を手で編集しないでください。

各ページの `<head>` から `<title>` `description` `date` `tags` を読み取り、日付の降順で並べます。手元で先に確認したい場合はこれを実行します。

```
python3 scripts/build_index.py
```

## 構成

```
.
├── index.html               一覧（自動生成・手で編集しない）
├── assets/style.css         全ページで共有するスタイル
├── scripts/new_page.py      ページの雛形を作る
├── scripts/build_index.py   一覧を生成する
└── <id>/index.html          ページ本体
```

## スタイル

色・タイポグラフィ・コンポーネントは `assets/style.css` に集約しています。色はすべて CSS 変数で定義し、ライト／ダーク両テーマに対応済みです。**ページ側で色を直接書かず、変数を使ってください。**

| クラス | 用途 |
| --- | --- |
| `.masthead` / `.eyebrow` / `.lede` | ページヘッダー |
| `.premise` | 前提・注記のボックス |
| `.matrix` / `.row` / `.verdict` | 比較マトリクス（横スクロール対応） |
| `.chip.is-block` / `.is-cond` / `.is-ok` | 判定チップ（赤／黄／緑） |
| `.card-list` | 並列する項目のカード一覧 |
| `.steps` | 番号付きの手順リスト |
| `.entries` | トップページの一覧 |

新しいコンポーネントが必要になったら `assets/style.css` に追加し、この表も更新します。

## 書き方

- 読み手は社内の人とは限りません。前提を明示してから本題に入ります
- 番号付きリストは、実際に順序に意味がある場合だけ使います
- 確度が低い部分は、低いと明示して書きます
- 情報の鮮度が重要な内容は、フッターに基準日を書きます
